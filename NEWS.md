# horizons (development version)

# horizons 0.12.0

## Changes

* `select_training()` refuses a zero-length `scope`, `space`, `metric` or `depth` as an input error; before, an empty `depth` ran with no depth at all.
* `average()` keeps and averages a response named `filename`; it drops only the OPUS input's meta column of that name.
* `select_training()` refuses a pool whose spectra are all the same after the similarity transform, with an input error, whether `ncomp` is a count or a proportion (#259).
* The validator gives an ensemble interval bundle whose default level is outside (0, 1) its own finding, as it does a fit's, rather than one blaming the calibration set.
* `step_select_correlation()`, `step_select_cars()` and `step_select_boruta()` no longer fail at `prep()` when every band they are given is near-constant: they keep no band, as their warning says, and `bake()` returns the other columns.
* `add_response()` and `parse_ids()` refuse a column named `.flag`, the column horizons reserves for the rows its steps flag, as an input error at their doors, as `spectra()` does; before, a `parse_ids()` token of that name marked every row as flagged.
* At the smallest calibration set CV+ accepts, `ensemble()` reports its in-sample interval diagnostics (`oof_coverage`, `mean_width`) as `NA`, with a note on the log saying why, as `fit()` does, rather than `NaN` with no word.
* The custom recipe steps (`step_transform_spectra()`, `step_select_boruta()`, `step_select_cars()`, `step_select_correlation()`) declare the packages a parallel worker needs, so resampling them on a multisession plan no longer fails every fold with "no applicable method" (#238).
* Breaking: fifteen internal helpers are no longer exported, among them `safely_execute()`, `build_recipe()` and `fit_uq()`. Reach one with `horizons:::` if you relied on it.
* `?horizons_conditions` documents the classes of horizons' errors and warnings: every error carries `horizons_error` and one kind (`input`, `validation`, `dependency`, `run`, `internal`), and every warning `horizons_warning` and one topic. The row-alignment check, a broken internal invariant, now raises `horizons_error_internal`.
* horizons now requires rlang 1.2.0 and cli 3.4.0.
* Every verb validates the object it is given, `predict()` included (#234). An object edited by hand or saved by an earlier version is refused with a `horizons_error_validation` whose `findings` field lists what is wrong, and which says how to rebuild it. Fits saved under 0.10.0 or 0.11.0 no longer predict: re-run the pipeline.
* Duplicate or missing sample ids before `average()` no longer warn; `average()` and every later verb refuse them.
* Evaluation checkpoints written by earlier versions are re-evaluated rather than reused.
* `spectra()` refuses a source column named `.flag`.
* Development builds say so when attached, and name the command that installs the latest release.
* `evaluate()`, `fit()`, `ensemble()` and `select_training()` take a `control` argument made by the new `control_horizons()`. Their `allow_par`, `parallelize_over`, `output_dir`, `chunk_size` and `verbose` arguments move into it, a breaking change. A verb refuses a control field it does not use, and records the control it ran with on the slot it writes.
* The row minimums for intervals, the applicability domain, the degradation check and the resemblance check can be set through `control_horizons()`.
* `verbose` defaults to `getOption("horizons.verbose", TRUE)` in those four verbs and in `average()`.
* `select_training()`'s `seed` defaults to 307, as the other verbs' do. The neighbour draw does not use the seed; the clusters of `scope = "cluster"`, and the resemblance check's reference sample on more than 2000 rows, change.
* `evaluate()`'s `"auto"` parallel axis no longer chooses the configs axis without an `output_dir`, and `parallelize_over = "configs"` without one is refused (#233).
* With `allow_par = TRUE` and no usable backend, the verbs warn once with a `horizons_warning_substitution`, recorded on the log, and run sequentially. The advice to install mirai or RhpcBLASctl is gone.
* `evaluate()`'s worker payload limit keeps a `future.globals.maxSize` larger than 1 GiB; set `max_worker_payload` to lower it.
* Breaking: `evaluate()`'s all-failed abort is `horizons_error_all_configs_failed` (with `horizons_error_run`), not `horizons_all_configs_failed`, and its refusals carry `horizons_error_input` (`metric`, the configurations, the window, checkpoints from another run, a training part without more rows than folds), `horizons_error_dependency` (a parallel run under `devtools::load_all()`, or with workers on another version of horizons) or `horizons_error_internal`.
* Each configuration `evaluate()` runs is one unit: a failure is recorded on its row with the step it arose in and its root class, filling `evaluation$results$class`; `control_horizons(keep_traces = TRUE)` keeps the backtrace in a new `trace` column; `debug = TRUE` runs in the session and stops at the first failure with its backtrace.
* A configuration that fails on any cross-validation fold is no longer ranked on the folds that survived (#101): a candidate missing a fold is left out of the choice of hyperparameters, a configuration with no complete candidate fails with the fold's error, and a cross-validated metric undefined on a fold is `NA`.
* A configuration whose final fit fails is recorded as failed, not as a success with `NA` test metrics (#102).
* A configuration's warnings are those of the hyperparameters it chose, not of every candidate tuned (#109).
* A recipe step's error is recorded with its class, also when it is raised inside tuning.
* `evaluate()` stops early, with `horizons_error_systemic` and the results so far, when the first configurations fail the same way across at least two models (`control_horizons(breaker = )`, 3 by default, `FALSE` to turn it off), or when a parallel worker dies. Their failures are not checkpointed.
* A parallel worker that dies during a Bayesian search now stops the run as systemic too, and a Ctrl-C during the search stops the call. tune caught both there, so the configuration came back as a search that stopped early and was checkpointed.
* Before a parallel run, on either axis, `evaluate()` checks that its workers load the same horizons.
* `evaluate()` warns once per kind at its end, recorded on the log first: some configurations failed (`partial_failure`); a configuration's Bayesian search stopped early, keeping the iterations it finished, or kept the grid's choice because it failed before any iteration or added nothing (`substitution`, #209); a stratified draw fell back to an unstratified one (`substitution`); configurations without a value of the ranking metric were left out of the ranking (`skipped`, also in `fit()`); the response trim could not run (`skipped`); the smallest fold is small (`quality`).
* When configurations were evaluated but none has a value of the ranking metric, `evaluate()` returns with `best_config = NA` rather than aborting, and `fit()` asks for another `metric`, suggesting only metrics that rank.
* `evaluate()` no longer refuses fewer than `2 * cv_folds` rows. It refuses a training part without more rows than `cv_folds`, which rsample cannot fold, and warns (`horizons_warning_quality`) when the smallest assessment fold has fewer than 10 rows.
* A checkpoint file `evaluate()` cannot use no longer warns: it is a note in the object's log and a line in the progress tree, and its configuration is evaluated again.
* Test metrics that cannot be computed (fewer than two rows with a prediction) are `NA` with the reason on the row, not `NA` with no reason and a stray warning; an ensemble's `improvement` is `NA` rather than `+Inf` when the ensemble or every member has no value of the rank metric, and the ensemble's contract and summary accept it. The Bayesian search's own warnings are no longer hidden.
* In `evaluate()`, a model whose tuned parameters are all whole numbers, with no more combinations than the grid and the Bayesian search would try together (plsr's `num_comp` on a short spectrum), is tuned over every combination with no Bayesian stage, rather than by a search that ran out of values to propose and was reported as failed.
* Breaking: `fit()`'s refusals carry `horizons_error_input` (the object, `metric`, the split, the outcome range, the trim request, the cold start's configurations), its all-failed abort is `horizons_error_all_members_failed` (with `horizons_error_run`), not `horizons_all_members_failed`, and its warning that every member fell below the prune threshold is `horizons_warning_quality`, not `horizons_below_threshold_warning` or `horizons_pruned_fallback_warning`.
* Each member `fit()` fits is one unit: a failure is recorded with the step it arose in and its root class in `models$results$class`, the member's own warnings are in `models$results$warnings`, and `control_horizons(keep_traces = TRUE)` keeps the backtrace in `trace`; `debug = TRUE` runs in the session and stops at the first failure with its backtrace.
* A member whose out-of-fold fits fail on any fold is a failed member, with the fold's error, rather than a success with incomplete out-of-fold predictions (#101) or an abort of the whole `fit()` (#102). The warm-start re-tune chooses only among candidates scored on every fold, and the member's warnings say how many were left out.
* `fit()` no longer loses prediction intervals, measured coverage or the applicability domain silently (#145): each that could not be computed, and UQ and AD switched off below `min_calib_rows`, is named in one `horizons_warning_skipped`, on the log, whatever `verbose` is. A bug inside them stops `fit()` instead of leaving a member without them.
* A member whose warm-start Bayesian search failed keeps what it finished and is named in one `horizons_warning_substitution` (#209); a stratified draw that fell back warns the same way.
* A member's warnings are those of the hyperparameters its re-tune chose (#109).
* `fit()` stops early, with `horizons_error_systemic` and the members so far, when its first members fail the same way across at least two models (`control_horizons(breaker = )`) or a parallel worker dies, during the warm-start Bayesian search too; a Ctrl-C during that search stops the call. Before a parallel run it checks that its workers load the same horizons.
* `fit()` warns once at its end when some members failed (`horizons_warning_partial_failure`), and records as notes on the log a member's workflow stored unslimmed and in-sample interval diagnostics that could not be computed.
* `models$results$degraded` is `NA` when the degradation check could not run (too few test rows, no finite cross-validated RPD, constant test outcomes), with the reason in the member's warnings and a `horizons_warning_skipped`, rather than `FALSE`.
* A member's cross-validated metrics in `models$results` average every fold or are `NA`, as `evaluate()`'s do, with their standard errors over every fold.
* `fit()`'s cold start no longer refuses fewer than `2 * cv_folds` rows. On either path, as `evaluate()` does, `fit()` refuses no more rows than `cv_folds` to draw its folds from (the training part less any calibration rows), and warns (`horizons_warning_quality`) when its smallest assessment fold is small.
* `fit()`'s warm-start re-tune grids a search space whole, with no Bayesian stage, when every tuned parameter is a whole number and the space has no more points than `grid_size + final_bayesian_iter`, as `evaluate()` does. At the defaults that is every plsr member: each `num_comp` up to its cap is tried, rather than a search started from `evaluate()`'s choice.
* A failure horizons reports keeps its location and fold count however long its cause: only another package's message is cut at 300 characters, in `evaluate()` and `fit()` alike.
* A run of `evaluate()` or `fit()` stopped before any configuration or member finished carries a results table with every column and no rows.
* `fit()`'s result is refused when a UQ bundle holds fewer finite scores than its level needs, or when its members' out-of-fold predictions do not cover the same rows.
* `predict()` predicts each configuration as a unit of its own: under `config = "all"` a configuration that cannot predict comes back as `NA` rows and is named in one `horizons_warning_partial_failure`. When nothing can be predicted (the configuration asked for, every configuration, or any member of an ensemble or its combination), it aborts with `horizons_error_prediction_failed`, the failures in its `results` field. `ensemble()` aborts with the same class when a member cannot predict the test rows.
* `predict()` bakes `new_data` through each configuration's recipe first: a row flagged on arrival (`.flag`) or non-finite after the recipe is returned as `NA` and named in one `horizons_warning_flagged`, and an ensemble returns `NA` for a row any member could not use.
* `predict()`'s interval and applicability-domain columns are present whenever they were asked for and a bundle exists. One that cannot be computed is `NA` and named in one `horizons_warning_skipped`, rather than the columns disappearing. Under `abstain_ood = TRUE`, a configuration whose applicability domain cannot be computed returns `NA` predictions.
* Breaking: `predict()`'s `interval` defaults to `NULL`: intervals wherever a UQ bundle exists, silently none elsewhere. An explicit `interval = TRUE` on a configuration or ensemble without one returns `NA` bounds and a `horizons_warning_skipped` naming it, and the ensemble's message about missing intervals is gone (#145).
* Breaking: `predict(abstain_ood = TRUE)` refuses, with `horizons_error_input`, any requested configuration without an applicability-domain bundle.
* Breaking: `predict()`'s warnings are raised once each, at the end of the call, by topic: `horizons_warning_input` for an ignored `level` (was `horizons_input_warning`); `horizons_warning_quality` for intervals on a selected training set or after a response trim (was `horizons_select_warning` and `horizons_response_trim_warning`, and now only when intervals are returned) and for a warning another package raised while predicting; `horizons_warning_applicability` for winsorized predictions. Each carries its record in the field `log`, and `options(warn = 2)` ends the call with `horizons_error_promoted_warnings`, the predictions in its `object` field. Its refusals carry `horizons_error_input` and `horizons_error_missing_package` (kind `horizons_error_dependency`).
* `predict()` on an ensemble returns its predictions in `new_data`'s row order, works for a single row of `new_data` with intervals (#235), and a `new_data` of zero rows returns zero rows.
* Breaking: `step_select_cars()` runs as its authors' code (libPLS's carspls) runs it, with the randomised sampling of Li et al. (2009) (#106). Each iteration weights the bands afresh from a PLS fit on an 80% Monte Carlo sample, at the component count cross-validation chooses for the full set, cuts them to the next iteration's share on an exponentially decreasing schedule, and draws as many times as there are bands, keeping the bands drawn; the weights had accumulated across iterations. After the loop every iteration's set is scored by 5-fold cross-validation over all the rows, on one partition shared by every set, at its best component count up to 30, and the lowest-scoring set is returned; it had scored each iteration by leave-one-out on its own sample at up to five components and returned a rerun's set. The trained step records the path (each iteration's representatives, band count, score, standard error and component count), and `retained_all` when the full set scores lowest. The bands kept change for every CARS configuration. In validation it is level with no selection on organic carbon from about 200 samples and trails it by about 4% at 100; compare it against `feature_selection = "none"` in `evaluate()`.
* `step_select_cars()` and `step_select_boruta()` represent each cluster of correlated bands by its middle band rather than its first, which can change the bands they keep.
* `step_select_cars()` drops near-constant bands before clustering, as `step_select_boruta()` does, so a constant band no longer fails the configuration. Both judge a band near-constant against the spectrum (a variance not finite, zero, or at most a hundred-millionth of the median band's) rather than an absolute 1e-10, which dropped informative second-derivative bands, and record the count as `n_constant`, shown by `print()`, instead of printing it at every prep.
* A selection step with too few bands to select from (`step_select_boruta()` or `step_select_cars()` with fewer than two after dropping near-constant bands, `step_select_correlation()` with fewer than five, for the three windows its threshold needs) keeps them and warns with `horizons_warning_skipped`, instead of failing, warning from base R, or reporting a substitution.
* `step_select_correlation()` warns with `horizons_warning_substitution` and records `retained_all` on the trained step when no window clears its threshold and it keeps every band; it printed a message. `step_select_cars()` no longer keeps every band when its scoring fails (#105).
* The selection steps have `tidy()` methods, their `print()` lines no longer run together, and `bake()` on new data missing a selected column names the missing columns (#109).
* Breaking: the selection steps' refusals carry `horizons_error_input` (wrapped by recipes in `recipes_error_step`, so test with `rlang::cnd_inherits()`); a failed Boruta run is `horizons_error_boruta` (kind `run`; was `horizons_boruta_error`), with Boruta's error in its message; Boruta's warnings are `horizons_warning_substitution` (it selected nothing) and `horizons_warning_quality` (it confirmed nothing; both were `horizons_boruta_warning`); the PLS engine's component cap is `horizons_warning_substitution` (was `horizons_pls_warning`).
* `evaluate()` and `fit()` record on their log, once per configuration and for every model, a selection step that kept every band, confirmed nothing or had too few bands to select from, read from the configuration's final fit.
* `ensemble()` builds its meta-learner as one unit: when it cannot be built it aborts with `horizons_error_ensemble_failed`, the failed step and cause in its `results` field (shaped as `horizons_error_prediction_failed`'s), including when a member cannot predict the test rows. Its tuned meta-learners choose hyperparameters only among candidates scored on every fold, as `evaluate()` and `fit()` do (#101). It honours `control_horizons(debug = , keep_traces = )`. Warnings other packages raise while it is built are kept in the new `ensemble$warnings`, rather than re-raised one by one, with the candidates left out of the choice and any CV+ intervals not computed.
* `ensemble()` says, with one `horizons_warning_skipped` whatever `verbose` is, when it could not calibrate CV+ intervals, and why, rather than printing a note only under `verbose`; its leave-self-out coverage warning is `horizons_warning_quality` (#145).
* Breaking: `ensemble()`'s refusals carry `horizons_error_input`; `fit()` and `ensemble()` refuse a `compute_uq` that is not `TRUE` or `FALSE`, and `fit()` a `compute_ad` likewise.
* Breaking: `select_training()` returns the training set on the library's own columns at the wavenumbers the targets share with it, with nothing interpolated (#236). Targets on a coarser canonical grid (4 or 8 cm-1 against a 2 cm-1 library) get the library's values at their wavenumbers. Target columns the library lacks (a wider range, a finer or offset step) are named in one `horizons_warning_coverage`, and `predict()` uses only the columns the model was trained on. Targets that share no column with the library, or whose wavenumbers lie on no grid aligned with the library's (an instrument's own axis), are refused, naming the `standardize()` call that puts them on the library's grid. The endpoint clamp, the finer-targets warning and `provenance$standardization$reconciliation` are gone, and `selection$reconciliation` now records which target wavenumbers the training set has.
* `select_training()` searches targets that fall short of the library's range by any amount on the overlap, with one `horizons_warning_coverage`, where more than 50 cm-1 was refused. Its coverage warnings are written to the returned object's log and raised once, at the end of the call.
* `select_training()` refuses, with `horizons_error_input`, a library and targets standardized differently: one baseline-corrected and the other not, or both corrected over different ranges (#107). For a registered library this is checked before it is downloaded.
* `select_training()` refuses a target set or a library with fewer than two wavenumbers, and a gapped axis, with `horizons_error_input` (was `horizons_input_error`, or a base R error for one wavenumber), and checks the targets' axis before a registered library is downloaded. A `window` that does not fit in the stretch of the library the targets cover is refused with `horizons_error_input`, in cm-1 (was an unclassed error from prospectr).
* `select_training()` writes every warning to the returned object's log and raises it once, at the end of the call, each with a topic class: `horizons_warning_input` (pool and targets in different photometric units), `horizons_warning_coverage` (draws short of `k`, now with targets that had no defined distance), `horizons_warning_skipped` (the resemblance check, a similarity space or library that could not be cached), `horizons_warning_applicability` (targets beyond the library's spread). `horizons_select_warning` is gone. A cached space rebuilt, and a first-use space that could not be built, are notes on the log, not warnings.
* `select_training()` leaves out of the similarity space a target or library spectrum flagged by an earlier step, naming the targets in one `horizons_warning_flagged`; it refuses only when every target or every library row is flagged. Cached similarity spaces are rebuilt once.
* `select_training(properties = NULL)` skips a response with no measured library rows, or fewer than `k`, with one `horizons_warning_skipped`, rather than refusing; a named one is still refused.
* `select_training()` keeps going when the twin subtraction empties one property, with one `horizons_warning_partial_failure`, and aborts with `horizons_error_selection_failed` only when it empties every property. `x$selection$settings$properties` lists the properties actually drawn for.
* `select_training()` gives every target `k` rows after the twin subtraction, fetching spares when a row it drew was another target's twin, or records it as a short draw (#149); its `target_distances` are over the rows it kept.
* `x$selection$pool_sizes` under `scope = "global"` counts, per property, the returned rows that carry it, so drawn no longer exceeds available (#153).
* A cached registered library is rebuilt, after asking as on first use, when it was built by an earlier version of horizons (#154). Every existing `"kssl"` cache is rebuilt once, a 436 MB download. A library built but not moved into the cache is returned with a `horizons_warning_skipped`, rather than refused.
* Building a registered library no longer deletes the downloaded source files it reads.
* `select_training()` refuses with `horizons_error_input`, before any download, a `library` that is not a `horizons_data`, a library object, a registered name or an existing file; its argument refusals report every problem in one condition with a `findings` field and print nothing. Its errors take the conditions contract's classes (`horizons_error_input`, `horizons_error_validation`, `horizons_error_consent`, `horizons_error_download`; were `horizons_input_error`, `horizons_validation_error`, `horizons_consent_error`, `horizons_download_error`). It refuses a fixed `clusters` above the number of targets, before any download, and a PLS space with no more measured rows than `ncomp`, which reached unclassed errors in `stats::kmeans()` and pls. A `mask` removing more than 90 % of the similarity space is no longer refused.
* `select_training()` no longer accepts `control_horizons(keep_traces = )`.
* `spectra()` reads a character vector of files and directories, OPUS or CSV, into one object, a directory of CSV files included (#224). Each file is read on its own: one that cannot be read, or holds no absorbance block, is dropped and named in one `horizons_warning_partial_failure`, and when none can be read the call aborts with `horizons_error_read_failed`, one row per file in its `results`. opusreader2's own warnings are no longer muffled: each is passed on as a `horizons_warning_quality`, except one raised while parsing a file's metadata, which horizons does not read, recorded as a note on the log. opusreader2 raises one for every OPUS file acquired west of Greenwich.
* `spectra()` takes each OPUS file's absorbance block by name (`ab`, then `ab_no_atm_comp`), not the first block on its list; a file with neither is dropped, naming its blocks (#191).
* `spectra()` puts files whose whole axis drifts by less than 1% of the step, as scans from different sessions do, on one grid, with one `horizons_warning_substitution`, so `spectra() |> parse_ids() |> average()` no longer fails on them (#224). It refuses a meta column whose type differs between files.
* `spectra()` drops a CSV file whose columns cannot be read as spectra (no id column, no wavelength columns, or one not numeric or not named by wavenumber) by name, with its cause and remedy, as it drops an OPUS file with no absorbance block; when every file fails the call aborts with `horizons_error_read_failed`. A data frame's columns are still refused at the door. A wavelength column with no value in any row is read as missing values.
* `spectra()` refuses a wavelength column whose name is not a wavenumber, and every verb refuses an object whose predictor names do not all read as wavenumbers (#121).
* `standardize()` keeps and flags (`.flag`) a spectrum it cannot use, one with a non-finite value among those it returns or with no spread (every value equal), with one `horizons_warning_flagged`, where it aborted on non-finite values; `evaluate()`, `fit()`, `predict()` and `select_training()` leave flagged spectra out. The convex-hull baseline is fitted to the spectra not flagged. A spectrum missing a value anywhere between its first and last points is flagged, never interpolated across, on the grid or off it; one whose points end before the grid's is flagged rather than extrapolated, and the warning gives the range such spectra cover so a `trim` can keep them. A spectrum on a coarser grid of its own, read beside finer ones, is put on the grid from its own points.
* Every verb after `average()` refuses a spectrum with no spread that is not flagged, as it refuses a non-finite value. An object standardized before this release that holds a flat spectrum is refused at the door.
* `standardize(force = TRUE)` keeps the record of a hull an earlier call fitted, and `select_training()` compares the ranges the hulls were fitted over (`data$standardization$baseline_range`).
* `step_transform_spectra()` refuses an unknown `preprocessing` when the step is added (#199), returns a spectrum with a non-finite value or no spread as `NA` whatever the method, naming it by sample id in one `horizons_warning_flagged`, and has a `tidy()` method (#109).
* `spectra()`, `parse_ids()` and `standardize()` take `verbose`, defaulting to `getOption("horizons.verbose", TRUE)`, raise their warnings once at their end with a topic class after writing them to the object's log, and refuse with classed conditions. `parse_ids()` no longer warns on CSV or tibble data; `too_few = "na"` and `standardize(force = TRUE)` report in verbose output instead of warning. `horizons_standardize_warning` is gone. The empty-grid refusal of `standardize()` reports the data's range and says to widen `trim` or reduce `resample` (#197).
* horizons requires prospectr 0.2.10 or later.
* `add_response()`, `average()`, `configure()` and `validate()` refuse with classed conditions that name the call and carry their details as bullets, raise their warnings once at their end with a topic class after writing them to the object's log, and report what was asked for in verbose output and a log note rather than a warning. `add_response()`, `configure()` and `validate()` take `verbose`, defaulting to `getOption("horizons.verbose", TRUE)`. `add_response()` warns `horizons_warning_coverage` when under half the samples match; at half or more it reports the unmatched samples. Re-configuring warns only when it discards an evaluation or a fit, and says when it cleared a validation and its response-trim request; re-validating no longer warns. `validate()` no longer warns that Cubist may not finish.
* Breaking: `add_response()`, `average()`, `configure()` and `validate()` refuse with `horizons_error_input`, not `horizons_input_error`, `horizons_configure_error`, `horizons_validate_error`, `horizons_validation_error` or `horizons_data_error`; `average()`'s abort when every sample is dropped is `horizons_error_qc` (kind `run`), not `horizons_qc_error`; and `horizons_validate_warning` is gone with the Cubist warning.
* Breaking: the outcome range and variance checks that `configure()` shares with `evaluate()`, `fit()` and `ensemble()` refuse with `horizons_error_input`, not `horizons_input_error` (and the range check no longer adds `horizons_configure_error`).
* `average()` records on the object's log every sample whose replicates all failed quality control, under every `on_all_outliers` mode (a `horizons_warning_quality` under `"warn"`, a note under `"keep_best"` and `"drop"`), and the metadata columns it drops (#231). When every sample is dropped it aborts with `horizons_error_qc`, the samples in its `results`.
* `average()` drops a metadata column whose values differ within any sample, as documented, where it kept the column filled with `NA` (#226). It leaves a replicate a step flagged (`.flag`) out of quality control and the mean, and flags a sample only when every replicate is flagged.
* `average()` no longer refuses a spectrum that is not finite or has no spread; `standardize()` decides, so `spectra() |> parse_ids() |> average() |> standardize()` keeps and flags it. Quality control fails a replicate it cannot correlate, such as a flat scan, where it was averaged in, and sets it aside as it does a flagged one, so a sample of two scans with one flat is the other scan whichever runs first. A uniform metadata column keeps its replicates' shared value when the first replicate lacks it.
* `average()` treats an `Inf`, `-Inf` or `NaN` in a replicate as a missing value, as it does `NA`: quality control correlates replicates over the bands they share, and the mean at each band uses the replicates with a value there, so a sample with one such scan is kept whichever of `average()` and `standardize()` runs first. A band no replicate has is `NA`, not `NaN`, and `standardize()` decides on it.
* `average(on_all_outliers = "keep_best")` keeps the replicate with the highest mean correlation against the sample's other replicates, measured before quality control removes any, where it kept the last one the removal left, which could be a worse scan. A tie goes to the earlier scan, so a pair that fails quality control now keeps its first scan, not its second (#109).
* `validate()`'s spectral outlier check compares each sample's distance with its exact in-sample reference distribution, a scaled Beta, rather than chi-squared, which could not flag any sample when many components were kept for the sample count (#227). It runs from three samples rather than five, flags somewhat more samples on small sets, and leaves flagged rows out, as the response outlier check now does too. Asked to remove spectral outliers, it refuses a `spectral_threshold` that flags every sample. A check that could not run is one `horizons_warning_skipped` and reads "not run" in the report.
* A grid candidate that fails on every fold is counted among the candidates left out of the choice of hyperparameters, in `evaluate()`'s, `fit()`'s and `ensemble()`'s notes (#249).
* `average()`, `standardize()`, `validate()` and `parse_ids()` refuse an evaluated or fitted object at their door when they would change its data; `parse_ids()` refuses to rename the rows of a `select_training()` result, and a format token named like a column already present.
* `provenance` is retired. The standardization record is now `data$standardization`, holding what the verbs read: whether the spectra carry a convex-hull baseline and over which range, and the axis's range and grid. `spectra()`, `parse_ids()`, `standardize()`, `average()` and `add_response()` record each call's source and settings as a note on the object's log, and the log gains a `time` column, so its first row says when the spectra were read; `spectra()`'s note names the horizons version. `print()` counts the log's warnings and notes, and `summary()` lists every row. `selection$targets$source` is read from the targets' `spectra()` note, and for targets read from a data frame it is `"data frame"` where it was `"tibble"`. `average()` no longer records `source_ids`.
* `average()`'s verbose output counts the flagged replicates of a sample dropped under `on_all_outliers = "drop"` once, as left out, and no longer also among the replicates the quality check removed.
* An object made before this change is refused with the remedy of re-running the pipeline. A cached `"kssl"` library is rebuilt once on its next draw, which downloads its 436 MB of source tables again and asks first.
* `fit()`'s applicability domain no longer warns when the training rows are fewer than the predictors, which on full spectra was nearly every fit: the shrinkage covariance is built for that case and the out-of-domain cutoff is calibrated on held-out rows (#237).
* Tuning metrics for an untransformed response (`transformation = "none"`) are clamped to `outcome_range`, as every other score already was, and so is the ensemble's meta-learner tuning (#104). Cross-validated scores, and where predictions left the range, rankings and chosen hyperparameters, can change. A resumed `evaluate()` re-evaluates every configuration once. `horizons_metric_set()` and `needs_back_transformation()` are removed.
* `fit()`'s warm-start Bayesian search starts from the member's seed, so its result does not depend on how the grid stage left the random stream (#151). The warm-start grid holds `max_points` rows when the sample draws the best point (#228), and is drawn from the candidates without it, so every overflowing starting grid changes; the best point is matched at a tolerance relative to its value, so a best penalty near 1e-9 no longer takes its neighbours for itself. Together these can change a warm-started member's chosen hyperparameters once. A best row with a missing value starts from the space-filling grid rather than erroring (#229).
* After a response trim, an ensemble's CV+ intervals are calibrated on the trimmed training rows too, predicted by members that never trained on them, so coverage over new data as a whole is at the level, as it is for a fit's, and `predict()` no longer warns about the fences (#103). The coverage is marginal: a sample whose outcome lies far outside the fences is rarely inside its interval. `ensemble$uq$calib` gains `sample_id`.
* `ccc_vec(na_rm = FALSE)` returns `NA` on a missing value, as `rpd_vec()` and `rrmse_vec()` do (#176).
* Measured coverage on the held-out test rows is reported beside the nominal level wherever intervals are shown: `print()` and `summary()` of a fit, and `ensemble()`'s summary, `print()` and `summary()` of an ensemble, which now measures its CV+ coverage (`ensemble$uq$test_coverage`, `test_mean_width`, `n_test`).
* A configured object without its recipe settings, outcome range or full tuning budget, or with a one-point grid while a Bayesian search runs, is refused at every verb's door with a remedy. So is an evaluated object without its configuration grid, an evaluation whose results lack the prune reading or, once screened, the settings each row was scored under, and a standardization record that has a convex-hull baseline but no hull range. Objects made before 0.10.0 lacked these fields, and they are no longer read through defaults (#212).
* A custom recipe step built before 0.10.0, whose selectors were stored in `columns`, is no longer re-prepped; rebuild the recipe (#212).
* `predict()` bins applicability-domain distances when calibration thresholds tie (duplicate calibration spectra), rather than dropping the applicability domain for the whole batch (#240).
* `evaluate()` checks `seed`, `prune` and `prune_threshold` at its door, and `fit()` checks `n_best` and `seed`. `seed` must be a whole number in every verb, so `ensemble()` now refuses a fractional seed it used to truncate.
* `step_select_correlation()` drops near-constant bands before scoring, as `step_select_cars()` and `step_select_boruta()` do, rather than passing base R's warning through. Its record counts them.
* `evaluate()`, `fit()` and `ensemble()` check, before any work, that the packages their configurations need are installed, as `predict()` does: each model's engine and the Boruta package for `feature_selection = "boruta"`. A missing one is refused once, with `horizons_error_missing_package`, naming each package and what needs it, rather than failing every configuration that needs it. A package missing where the work ran stops the run with `horizons_error_systemic` and the results so far, as a worker's death does.
* A stratified draw that comes out unstratified, because it failed or because rsample formed one stratum from the outcome (too little data, tied quantiles, a few-valued outcome pooled into one), is one `horizons_warning_substitution` in `evaluate()`, `fit()` and `ensemble()`, with rsample's words when it gave any. rsample's warnings no longer print mid-call, and a draw it left unstratified silently is now reported. A draw rsample stratifies on fewer bins than asked is a note on the log and a line in the tree. `ensemble()`'s meta-learner and CV+ folds fall back to an unstratified draw when the stratified one fails, as `evaluate()`'s and `fit()`'s do.
* A write to `evaluate()`'s `output_dir` that fails (the directory, the manifest or a checkpoint) stops the run with `horizons_error_systemic`, naming the directory, with the results so far, and leaves no temporary file behind. On the configs axis, a checkpoint a worker could not write is known only once every configuration has run, so `evaluate()` returns the evaluation with one `horizons_warning_skipped` naming the configurations a resumed run would evaluate again.

# horizons 0.11.0

## Changes

* PLS uses the CRAN `pls` package, through an engine horizons registers for `parsnip::pls()`, and so does `select_training(space = "pls")`; neither mixOmics nor the plsmod fork is needed, so horizons installs from CRAN apart from opusreader2 (#171). PLS tunes up to 30 components, capped by the predictors and the smallest fold's rows, where it searched only 1 to 4 (#216). Objects fitted with 0.10.0 that include a PLS member must be refitted to predict.
* The covariate API is removed (#134). No verb ever gave a column the `covariate` role, so it could be reached only by editing the role map by hand. `configure()` loses `expand_covariates` and `cov_fusion`, `config$configs` its `covariates` column and `config$expansion` its covariate entries, and `data$n_covariates` goes; `build_recipe()`, `predict()`, `print()`, `summary()` and `evaluate()`'s checkpoint fingerprint no longer handle covariates. Config ids change, so a checkpoint directory written by 0.10.0 is evaluated again rather than resumed. A `covariate` role, and an object whose `config$configs` still has a `covariates` column, are refused with class `horizons_validation_error`: give the column the `meta` role, or re-run `configure()` and the verbs after it.
* Checkpoint stores, run manifests and records written before 0.10.0 are evaluated again, not resumed (#201). `evaluate()` no longer reads the single-file `eval_checkpoint.rds`; a checkpoint row that does not record the training-data fingerprint and every setting the run records is re-evaluated instead of resumed with a warning; `monitor_evaluate()` refuses a manifest written by another version; and `validate()`'s `removal_detail` drops its always-`NA` `outcome` and `response_threshold` columns.
* `validate_horizons_fit()` checks the type of every column `fit()` writes to `models$results`, where the column is present, and names each column of the wrong type ("degraded is integer, not logical") (#203).
* `parse_ids()` refuses an evaluated, fitted or ensembled object. It rewrites `sample_id`, and the stored splits and models are keyed to it (#135).
* Each class is checked against everything it promises (#129). An evaluated object is checked against the base data contract as well as its evaluation, and an ensemble against its fitted models, evaluation and data. `ensemble()` checks the whole fitted object before it fits anything, as `evaluate()` and `fit()` already did. Two rules are new: the column with the `id` role must be `sample_id`, and `evaluation$results` must have exactly one row per configuration in `config$configs`. Every validation failure now aborts with class `horizons_validation_error`, including the checks that run first, which used to abort without it.
* `select_training()` validates the targets and the library before drawing. Targets need one row per sample with finite spectra, so replicate scans are averaged first. A library that has been through `configure()` or `validate()` is refused, and the selection record now identifies the targets in `x$selection$targets`: their source, row count and an id hash (#133).
* `evaluate()` and `fit()`, including the cold start, abort with class `horizons_input_error` when the outcome has zero variance, on the modelled rows or on the rows the models are fitted on; `validate()` is documented as an advisory report, and `summary()` suggests it only before `evaluate()` (#132).
* The object no longer carries the unused `artifacts` slot, `models$row_index` or `provenance$schema_version`, and `models$cv_predictions` gains `sample_id`. The validators no longer accept objects missing keys that current versions always write, so objects saved by earlier versions need a re-run.
* Attaching a development build says so and names the command that installs the latest release (`remotes::install_github("S-Leuthold/horizons@main")`); development builds carry a `.9000` version suffix.
* `needs_back_transformation()` no longer treats `"notrans"`, `"na"` or `""` as no transformation; `"none"` is the only such value, and every other value, `""` and `NA` included, returns `TRUE`. `back_transform_predictions()` treats `""` and `NA` as unknown transformations, as it already did `"notrans"` and `"na"`: the predictions are not back-transformed (they are still clamped to `outcome_range`), with a warning when `warn = TRUE`.

## Bug fixes

* `evaluate()` and `fit()` record when a Bayesian search fails or returns without running an iteration past the grid, and the grid's choice is kept, instead of reporting an ordinary success. `configure()` refuses `grid_size = 1` when `bayesian_iter` or `final_bayesian_iter` is above 0, where the search could never start (#209).
* `evaluate()` no longer refuses to resume a checkpoint written on the same data under another locale. The check compared a hash of the sample ids sorted in the session's collation; it now compares the recorded data fields (#213).
* `summary()` no longer closes the Data tree twice for an object with no outcome (#205).
* `step_select_correlation()` errors at `bake()` when new data lacks a wavenumber it selected, as `step_select_cars()` and `step_select_boruta()` do. It returned the data without its selected columns (#200).
* `print()` and `summary()` of a fitted object report the member `fit()` selected on cross-validation (`models$best_config`) and its test metrics, as `fit()`'s console does. They reported the member with the lowest test RMSE, a best-of-N on the held-out rows that could name a different configuration (#136).
* `add_response()` refuses an `NA` join key on either side and reports how many there are. Before, an `NA` key on one side was matched to an `NA` key on the other (#139).
* `predict()` no longer drops arguments it does not take without saying so. A `level` warns, with class `horizons_input_warning`, that it is ignored: intervals are at the level they were calibrated at, 0.90 by default. Any other unknown argument, such as a misspelled one, is an error (#141).
* `fit()` refuses an evaluated object whose response-trim request changed after `evaluate()`, instead of silently fitting with the trim `evaluate()` applied. `validate()` can record a new request on an evaluated object, but `fit()` reuses the rows `evaluate()` trimmed, so the new request never took effect. The error says what differs; re-run `evaluate()` to apply the current request (#137).
* `predict()`, `ensemble()` and `select_training()` now check that values attached to samples by position line up with their rows, and stop with a `horizons_internal_error` instead of mislabelling samples if a step upstream dropped or reordered rows. In `fit()` the same check keeps misaligned uncertainty scores from being stored; the member is then fitted without intervals (#140).

## Tests

Most of the work in this release went into the test suite. The aim was for every test to fail when the behaviour it checks breaks, and for the suite to show that it does.

* An audit of every test, made as 0.10.0 was released, found 43 tests that could not fail, six validator checks whose tests still passed with the check removed, and a leakage test whose outcome was random noise, so it could not see leakage. These have been fixed or replaced.
* All tests were then subjected to mutation testing, which makes small changes to the package's code and checks whether the tests catch them, and were updated based on the results. Across a sample of changes drawn from each of the package's files, the initial tests caught 64% of the mutations; the revised tests catch 81%.
* The test suite is also significantly faster. R CMD check on CI took 15 to 17 minutes at 0.10.0 and takes about 7 now. Fixtures that are slow to build are built once per R process, and tests that take 3 seconds or more run in a slow tier, which CI runs on pushes, nightly and before a release.
* Evaluating the tests also revealed a handful of latent bugs. These are documented (#226 to #229) and slated for fixes in 0.12.0. None are breaking, but they can affect averaging replicate scans when a metadata column varies within some samples, the spectral outlier check in `validate()` on small datasets, and the size of the warm-start grid `fit()` searches.

# horizons 0.10.0

First tagged release. It brings `main` up to date with the development branch, where horizons was rebuilt around an S3 approach: a single `horizons_data` object that each verb in the pipeline takes and returns, carrying the spectra, configuration, results and a record of how each step was run, from raw spectra to predictions. It is still pre-1.0, so the API may change between minor versions.

Earlier version numbers (0.8 and 0.9) were untagged development snapshots of a previous API, which this release replaces.

## Highlights

* `spectra()` reads Bruker OPUS files or a table of spectra. `parse_ids()` extracts sample identifiers from OPUS file names, and `average()` averages replicate scans with a correlation check that flags outlying scans.
* `standardize()` resamples spectra onto a common wavenumber grid anchored at fixed points, so spectra from different instruments or sources line up column for column. It can also trim the range, remove water bands and correct the baseline.
* `add_response()` joins laboratory measurements, and `configure()` builds the factorial grid of models, spectral preprocessing, feature selection and response transformations to compare. `configure(outcome_range =)` declares the physical range of the outcome, which every prediction respects.
* `validate()` checks the data and the grid before any modeling runs.
* `evaluate()` tunes and cross-validates every configuration. It checkpoints each configuration as it finishes, so an interrupted run resumes, and it runs in parallel on whatever `future` backend you register.
* `fit()` retunes the best configurations and fits the final models, with conformal prediction intervals (conformalized quantile regression) and an applicability-domain check that flags samples unlike the training data. It reports interval coverage measured on held-out test rows.
* `ensemble()` stacks fitted models with a penalized, weighted or XGBoost meta-learner, with CV+ prediction intervals.
* `predict()` returns point predictions, prediction intervals and applicability flags for new samples, from a single model or an ensemble.
* `select_training()` draws a training set for a batch of samples from a reference spectral library. The first registered library is the USDA NRCS Kellogg Soil Survey Laboratory MIR library from the Open Soil Spectral Library, built on your machine from the public files on first use.
* The recipe steps `step_transform_spectra()`, `step_select_boruta()`, `step_select_cars()` and `step_select_correlation()`, and the metrics `rpd()`, `rrmse()` and `ccc()`, are exported for use in your own tidymodels workflows.

## Breaking changes since 0.9.0

* The previous API (`create_project_data()`, `evaluate_models_local()`, `build_ensemble_stack()` and related functions) is removed, along with OSSL covariate prediction.
* `evaluate()` no longer creates its own parallel backend. Register one with `future::plan()` and use `allow_par` and `parallelize_over`; the `workers` argument is gone.
* Outcomes outside `outcome_range` are refused before tuning. The default range is non-negative, `c(0, Inf)` (#76).
* `validate()` no longer removes response outliers. `evaluate()` instead trims them from its training partition only, and the test rows are left as they are (#77).
* `fit()` scores on `evaluate()`'s train/test split rather than drawing its own.
* `step_select_boruta()` fails when Boruta fails, rather than falling back to a correlation filter (#75).

## Bug fixes

* The interval coverage `fit()` reported was an in-sample diagnostic; it is now measured on held-out test rows (#118).
* The DEGRADED flag in `fit()` fired on healthy fits. It now bootstraps the test RPD and flags a configuration only when the whole interval lies below the cross-validated RPD (#119).
* `ensemble()` failed on a fitted object read into a fresh R session.
* Failed and warned configurations now record their cause (#96).
* `average()`'s quality-control report no longer counts a sample whose every scan failed as clean (#89).
* `standardize(baseline = TRUE)` works on a single sample (#78).
* Tuning metrics are scored on the original response scale (#49).
